# steward 分发 / 安装说明

面向：把 steward 装到别人（领导 / 同事）的 macOS 机器上试用。

前提：macOS、Python 3.11+、内存 16GB 以上（跑 embedding + reranker 模型
峰值约 5~6GB，加系统开销）。**建议是 Apple Silicon**（有 Metal GPU 加速）；
Intel 芯片也能装能跑，但没有 Metal 加速，`search`/`tag` 会明显更慢。

---

## 一、这套东西怎么分成几块

| 块                                                                     | 谁来跑                               | 怎么给到对方                           |
| ---------------------------------------------------------------------- | ------------------------------------ | -------------------------------------- |
| **steward 代码**                                                       | 对方机器                             | pip 装一个 wheel 文件（很小，几十 KB） |
| **embedding + reranker 模型**（bge-m3 + bge-reranker-v2-m3，约 4.3GB） | 对方机器（进程内加载）               | 不用给——首次运行自动从 ModelScope 下载 |
| **打标签用的 2B 大模型**（llama-server 服务）                          | 暂时都跑在你（分发者）的机器上       | 对方不用装，CLI 指过来                 |
| **索引数据库**                                                         | 对方机器（`steward index` 时自己建） | 不用给，对方自己跑 index 生成          |

对方机器上：`index` / `search` / `duplicates` 全部本地跑，不发送任何文件内容；
只有 `tag` 会把文件片段发到你的机器做打标签推理。

## 二、分发者（你）这边要做的

### 1. 打包

```bash
cd /Users/kevinchow/CodeKevin/steward
source .venv/bin/activate
python -m build --wheel
# 产物：dist/steward-0.1.0-py3-none-any.whl
```

### 2. 把 wheel 交到对方手里

`.whl` 就是一个文件，模型不在里面，所以很小。按人数选：

| 方式             | 怎么做                                                                                                         | 适合                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **直接传文件**   | AirDrop / 邮件 / 企业微信 把 `.whl` 发过去，对方 `pip install ./steward-xxx.whl`                               | 1~几个人，最省事               |
| **共享位置**     | `.whl` 传企业网盘 / 共享盘，发链接                                                                             | 十几个人                       |
| **从 git 装**    | 对方 `pip install git+https://内部git地址/xxx/steward.git`，pip 现场构建，不用传 wheel 文件                    | 有内部 git，想让人自助升级     |
| **私有 PyPI 源** | 搭 `pypiserver` / `devpi`，或用公司的 Nexus/Artifactory，然后 `pip install steward --index-url http://内部源/` | 真变成常用内部工具、要频繁升级 |

现阶段（演示 + 几个同事）直接传文件就够，不用搭源。

### 3. 让 llama-server 监听局域网

对方机器要能连到你机器的 llama-server。默认它只监听 `127.0.0.1`（只有本机能
连），启动时加 `--host 0.0.0.0` 让局域网内其它设备也能连：

```bash
llama-server -m <模型路径> --mmproj <mmproj路径> --host 0.0.0.0 --port 8080 <其它你原本的参数>
```

第一次这么启动，macOS 可能弹窗问"是否允许接受传入的网络连接"，选允许。

查你自己机器的局域网 IP：

```bash
ipconfig getifaddr en0    # Wi-Fi
# 或 ipconfig getifaddr en1
```

拿到形如 `192.168.1.23`，对方要用的地址就是 `http://192.168.1.23:8080/v1`。

验证局域网能通（在对方机器上跑）：

```bash
curl http://192.168.1.23:8080/health
# 返回 {"status":"ok"} 就是通的
```

## 三、对方机器上的安装步骤

这一节假设对方已经通过 AirDrop 收到了 wheel 文件和两个模型文件夹，默认
都落在 `~/Downloads/` 下（AirDrop 收文件/文件夹的默认位置）。

### 0. 先确认环境，避免装到一半才发现不对

```bash
python3 --version     # 要 3.11 或更高
uname -m              # arm64 = Apple Silicon（有 Metal GPU 加速）
                       # x86_64 = Intel 芯片，也能装、能跑，但没有 Metal
                       # 加速，search/tag 会明显更慢，不是装不上，是体验打折

ls ~/Downloads/        # 确认实际收到的文件/文件夹叫什么——AirDrop 偶尔会
                       # 自动加后缀（比如 bge-m3 2），跟下面命令里的名字对
                       # 不上的话，以这里看到的真实名字为准，不要照抄
```

### 1. 把模型文件夹放到 steward 期望的位置

```bash
mkdir -p ~/Library/Application\ Support/Steward/models
mv ~/Downloads/bge-m3 ~/Library/Application\ Support/Steward/models/
mv ~/Downloads/bge-reranker-v2-m3 ~/Library/Application\ Support/Steward/models/

# 验证两个模型目录下都有 config.json（steward 判断"模型是否已就绪"就看这个）
ls ~/Library/Application\ Support/Steward/models/bge-m3/config.json
ls ~/Library/Application\ Support/Steward/models/bge-reranker-v2-m3/config.json
```

两条 `ls` 都能正常打印路径、不报错，才算放对了；报 `No such file or
directory` 说明文件夹名字或路径不对，回头核对第 0 步 `ls ~/Downloads/`
看到的真实名字。

### 2. 装 steward

```bash
# 建议单独建个虚拟环境，不污染系统 Python
python3 -m venv ~/steward-venv
source ~/steward-venv/bin/activate

# 文件名以 ~/Downloads/ 里实际看到的为准，版本号不一定是 0.1.0
pip install ~/Downloads/steward-0.1.0-py3-none-any.whl
```

依赖（torch / sentence-transformers / FlagEmbedding / modelscope 等）会自动
一起装，第一次比较慢（实测一台干净环境约 3~4 分钟，网速慢的话更久），
耐心等，装的时候可以顺便讲讲项目背景，不用干等着看进度条。

因为第 1 步已经把模型手动放到位了，接下来跑 `index`/`search` **不会**
触发 ModelScope 自动下载——那套自动下载是给"没有人当面 AirDrop"的场景
准备的，两条路都通，这次用手动放置这条。

### 3. 配置打标签服务地址（只有要用 `tag` 才需要）

```bash
# 写进 shell 配置，设一次就行
echo 'export STEWARD_LLM_BASE_URL=http://192.168.1.23:8080/v1' >> ~/.zshrc
source ~/.zshrc
```

（把 IP 换成分发者机器的实际局域网 IP。）

**这一步只对 `tag` 命令有效，而且只在分发者的笔记本开着、连着同一个
WiFi、`llama-server` 在跑的时候才连得通**——`index`/`search`/
`duplicates` 这三个命令不依赖这个，装完模型就能独立跑，不受这条限制。

### 4. 跑起来

```bash
# 对自己的文档建索引——模型已经在本地，这一步不会看到下载进度条，
# 直接开始扫描/提取/建索引
steward index ~/Documents

# 语义搜索——同样直接用本地已放好的 embedder + reranker
steward search "去年的报销发票"

# 查重复文件（不需要任何模型，纯哈希，最快）
steward duplicates ~/Downloads
steward duplicates                 # 不带目录 = 对已建索引的所有目录查重（含跨目录）

# 打标签（需要分发者的 llama-server 在线，见上面第 3 步的提醒）
steward tag
```
