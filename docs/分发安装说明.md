# steward 分发 / 安装说明

面向：把 steward 装到别人（领导 / 同事）的 macOS 机器上试用。

前提：对方是 Apple Silicon 的 Mac、有 Python 3.11+、内存 16GB 以上（跑
embedding + reranker 模型峰值约 5~6GB，加系统开销）。

---

## 一、这套东西怎么分成几块

| 块 | 谁来跑 | 怎么给到对方 |
|---|---|---|
| **steward 代码** | 对方机器 | pip 装一个 wheel 文件（很小，几十 KB） |
| **embedding + reranker 模型**（bge-m3 + bge-reranker-v2-m3，约 4.3GB） | 对方机器（进程内加载） | 不用给——首次运行自动从 ModelScope 下载 |
| **打标签用的 2B 大模型**（llama-server 服务） | 暂时都跑在你（分发者）的机器上 | 对方不用装，CLI 指过来 |
| **索引数据库** | 对方机器（`steward index` 时自己建） | 不用给，对方自己跑 index 生成 |

对方机器上：`index` / `search` / `duplicates` 全部本地跑，不发送任何文件内容；
只有 `tag` 会把文件片段发到你的机器做打标签推理。

## 二、分发者（你）这边要做的

### 1. 打包

```bash
cd /Users/kevinchow/CodeKevin/steward
source .venv/bin/activate
python -m build --wheel
# 产物：dist/steward-0.1.0-py3-none-any.whl
```

### 2. 把 wheel 交到对方手里

`.whl` 就是一个文件，模型不在里面，所以很小。按人数选：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **直接传文件** | AirDrop / 邮件 / 企业微信 把 `.whl` 发过去，对方 `pip install ./steward-xxx.whl` | 1~几个人，最省事 |
| **共享位置** | `.whl` 传企业网盘 / 共享盘，发链接 | 十几个人 |
| **从 git 装** | 对方 `pip install git+https://内部git地址/xxx/steward.git`，pip 现场构建，不用传 wheel 文件 | 有内部 git，想让人自助升级 |
| **私有 PyPI 源** | 搭 `pypiserver` / `devpi`，或用公司的 Nexus/Artifactory，然后 `pip install steward --index-url http://内部源/` | 真变成常用内部工具、要频繁升级 |

现阶段（演示 + 几个同事）直接传文件就够，不用搭源。

### 3. 让 llama-server 监听局域网

对方机器要能连到你机器的 llama-server。默认它只监听 `127.0.0.1`（只有本机能
连），启动时加 `--host 0.0.0.0` 让局域网内其它设备也能连：

```bash
llama-server -m <模型路径> --mmproj <mmproj路径> --host 0.0.0.0 --port 8080 <其它你原本的参数>
```

第一次这么启动，macOS 可能弹窗问"是否允许接受传入的网络连接"，选允许。

查你自己机器的局域网 IP：

```bash
ipconfig getifaddr en0    # Wi-Fi
# 或 ipconfig getifaddr en1
```

拿到形如 `192.168.1.23`，对方要用的地址就是 `http://192.168.1.23:8080/v1`。

验证局域网能通（在对方机器上跑）：

```bash
curl http://192.168.1.23:8080/health
# 返回 {"status":"ok"} 就是通的
```

## 三、对方机器上的安装步骤

### 1. 装 steward

```bash
# 建议单独建个虚拟环境，不污染系统 Python
python3 -m venv ~/steward-venv
source ~/steward-venv/bin/activate

pip install /path/to/steward-0.1.0-py3-none-any.whl
```

依赖（torch / sentence-transformers / FlagEmbedding / modelscope 等）会自动
一起装，第一次比较慢（可能十几分钟，torch 本身就不小），耐心等。

### 2. 配置打标签服务地址（只有要用 `tag` 才需要）

```bash
# 写进 shell 配置，设一次就行
echo 'export STEWARD_LLM_BASE_URL=http://192.168.1.23:8080/v1' >> ~/.zshrc
source ~/.zshrc
```

（把 IP 换成分发者机器的实际局域网 IP。）

### 3. 跑起来

```bash
# 对自己的文档建索引——第一次运行会自动从 ModelScope 下载 embedding 模型
# （bge-m3，约 2.3GB，带进度条，一次性），然后开始建索引
steward index ~/Documents

# 打标签（会连分发者的 llama-server）
steward tag

# 语义搜索——第一次会再自动下载 reranker 模型（bge-reranker-v2-m3，约 2GB）
steward search "去年的报销发票"

# 查重复文件（不需要任何模型，纯哈希）
steward duplicates ~/Downloads
steward duplicates                 # 不带目录 = 对已建索引的所有目录查重（含跨目录）
```

模型只在第一次用到时下载一次，之后缓存在
`~/Library/Application Support/Steward/models/`，不再重复下。

## 四、离线 / 内网无法访问 ModelScope 时（可选）

如果对方机器连不上 ModelScope，可以由分发者手动把模型拷过去：

```bash
# 分发者：打包模型目录
cd ~/Library/Application\ Support/Steward
zip -r ~/Desktop/steward-models.zip models/

# 对方：解压到同样位置
mkdir -p ~/Library/Application\ Support/Steward
cd ~/Library/Application\ Support/Steward
unzip /path/to/steward-models.zip
# 解压后应有 .../Steward/models/bge-m3/config.json 和 .../bge-reranker-v2-m3/config.json
```

代码里 "本地有就用本地的、没有才下载" 的判断标准是目录下有没有 `config.json`，
所以只要手动拷到位，就不会再触发自动下载。

## 五、常见问题

- **`steward: command not found`**：虚拟环境没激活，或者装到别的环境去了。`source ~/steward-venv/bin/activate` 后再试。
- **首次 `index`/`search` 卡在"从 ModelScope 下载"**：网络问题。确认能访问 modelscope.cn；或者走上面第四节手动拷模型。
- **`tag` 卡住 / 连接超时**：分发者的 llama-server 没开、没加 `--host 0.0.0.0`、或者两台机器不在同一局域网。先用 `curl .../health` 确认能通。
- **第一次 `index` 特别慢**：正常（下载模型 + 首次全量索引），之后是增量，内容没变的文件会跳过。
